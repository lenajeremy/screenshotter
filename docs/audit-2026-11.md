# Repository audit, 13 November 2026

Bugs, security problems, UI/UX improvements and performance improvements found by reading the code on branch `updates` at commit `7372e1b`. Nothing was changed: this is a list of findings with suggested fixes.

## How to read this

Each finding has a status:

- **Verified**: I read the code and, where marked "tested", reproduced it.
- **Reported**: found by a reviewer agent, and I have not re-read every line of it myself.
- **Plausible**: the code allows it, but it depends on browser or system behaviour nobody ran.

Items already listed in `docs/ui-audit.md` are left out.

## 1. Security

The threat that matters most here is **content written by an agent that was fed hostile text** (a web page it read, a file it was given), plus **a hostile website being captured**. Both reach code that trusts its input more than it should.

### SEC-1. Board SVGs can navigate the app or run script: the cleaner is a blocklist (High, verified and tested)

`src/board/core.ts:358-373` (`serializeSvg`, `safeAttr`), drawn raw by `src/studio/ui/board-canvas.js:157-175` and `core.ts:989-1009`.

Board HTML is cleaned once, when it comes in. After that the canvas and Preview insert `text`, `svg` and `defs` as raw HTML. The SVG cleaner removes a fixed list of tags and keeps everything else. Three things get through, each confirmed in WebKit and Chromium:

1. **A page redirect with no click.** `<svg><p><meta http-equiv="refresh" content="0;url=…"></p></svg>` survives when the SVG stays one layer (no drawable parts, more than 800 parts, or an icon). Inserted on the canvas, it navigates the page.
   - In the app, `AppDelegate.swift:203-212` hands any non-Studio address to `NSWorkspace.shared.open`, so opening the board opens an arbitrary URL, file or app link (see SEC-3). `data:` addresses are allowed to load inside the app window, where the native bridge is available (SEC-4). I did not run that last step in the app.
   - In the headless browser that draws thumbnails, it loads the attacker's page with web security off (SEC-2). Thumbnails are drawn automatically.
2. **Script links.** `safeAttr` rejects `javascript:` only after whitespace. Browsers also ignore control characters before it and newlines inside it. `href="\u0001javascript:…"` survives in text layers and `href="java\nscript:…"` in whole SVGs. The canvas blocks link clicks (`board-canvas.js:324`), but **Preview does not**, and Preview is served from the Studio's own address, so the script can call every Studio API.
3. **Global CSS.** `<style>` inside an SVG is kept (`core.ts:371`) and applies to the whole Studio page. It can hide or restyle the app's interface and load remote stylesheets (`@import`).

Fix:
- Replace the blocklist with an allowlist of SVG elements and attributes; drop every HTML element inside an SVG.
- Allow only `http:`, `https:`, `mailto:` and `#` in `href`, after stripping control characters and whitespace.
- Scope or drop `<style>` in SVGs. This also fixes BUG-8.
- Clean again in `applyOps` (`set` and `add` with `text`, `svg`, `defs`), since `/api/board/ops` accepts them raw.
- Add `Content-Security-Policy: script-src 'self'` (and no inline script) to the Studio page and a `script-src 'none'` policy to the board documents, as a second line of defence.

### SEC-2. The headless browser has web security switched off and also loads remote pages (High, verified)

`src/render/browser.ts:58-61` starts one shared Chrome with `--disable-web-security` and `--allow-file-access-from-files`. `src/capture/web.ts:177` and `src/capture/record.ts:193` open any URL in it.

A captured website can therefore read responses from any other origin, including the Studio on `127.0.0.1` (it can find the port by trying them; the CLI default is 4545) and devices on the local network. It can send the `x-screenshotter: studio` header, because the check that normally stops that is the one switched off. Through the Studio API it can read the library, take a screenshot of the Mac (`/api/capture/mac`), write house-style notes that agents later treat as instructions (`/api/house-style`), and post comments that are delivered into the user's agents as if the user wrote them (`/api/board/comment`).

Fix: use a second browser, started without those two flags, for anything that loads a remote page. Keep the relaxed one for local mockup and board documents only, and block navigation away from the local file in those pages.

### SEC-3. Any navigation is passed to macOS to open (High, verified)

`app/Sources/Screenshotter/AppDelegate.swift:203-217`. Every navigation that is not the engine's address, in any frame, with or without a click, goes to `NSWorkspace.shared.open(url)` with no check on the scheme. The same for new windows.

Fix: open only `http`, `https` and `mailto`, only for the main frame, and only when `action.navigationType == .linkActivated`. Do not allow `data:` in the main frame.

### SEC-4. The native bridge trusts any script in the window (High, reported)

`AppDelegate.swift:30, 248-344`. The message handler does not check which frame or address sent the message. Commands include `openURL` (any scheme), `readText` (clipboard), `setApiKey` and `setUnsplashKey` (replace saved keys), `restartEngine` and `dragFile` (any path). Combined with SEC-1 this is the route from a hostile board to the Mac.

Fix: reject messages unless `message.frameInfo.isMainFrame` and the frame's origin is the engine's. Limit `openURL` to web links and `dragFile` to the library.

### SEC-5. The local API has no secret (Medium, verified)

`src/studio/server.ts:476-477, 777`. The only checks are the `Host` header and a fixed header value, `x-screenshotter: studio`. Any local process can drive it, and so can any script that gets around the browser's cross-site rules (SEC-2).

Also, read-only routes need no header at all, and some have side effects: `/api/apps` boots a simulator, `/api/recipe-preview` and the other preview routes render, `/api/unsplash` spends the key's quota, `/api/board?id=scratchpad` creates a board. Another website can trigger these blind with an image tag once it guesses the port.

Fix: a random token per launch, given to the page by the app and required on every `/api/` request. Move side effects off GET.

### SEC-6. Files in the library are served as live web pages (Medium, verified)

`server.ts:105-120, 658-675`. `/file` serves anything under the library with its type by extension, including `.html` (the engine writes `<export>.html` companions) and `.svg`, from the Studio's own address and without the header. Opened directly, such a file runs its scripts with full access to the API.

`allowedFile` (`server.ts:176-180`) also compares paths without resolving symbolic links, so a link inside the library exposes whatever it points at.

Fix: send `Content-Disposition: attachment` or `Content-Security-Policy: sandbox` for `.html` and `.svg` (and `X-Content-Type-Options: nosniff` for everything); resolve with `realpathSync` before comparing.

### SEC-7. Shared templates are imported without checking (Medium, verified)

`src/studio/templates.ts:151-186`. A template file from someone else writes its embedded assets into the library with whatever extension their names carry (an `.html` file, see SEC-6), and its scenes are saved without going through `MockupInputSchema`, so they can point at any local file path. `/api/my-template/import` (`server.ts:839-844`) also reads the upload with no size limit.

Fix: allow only image extensions, check the bytes are an image, parse each scene with the schema, and use the size-limited `body()`.

### SEC-8. Writes and reads outside the library through the API (Medium, verified)

- `/api/mockup`, `/api/video`, `/api/sequence` accept `output` as any path (`src/render/mockup.ts:1207`), so a caller can overwrite files anywhere the user can write.
- `/api/bezels/import` (`server.ts:971-975`) reads any folder named.
- `adoptImage` (`src/board/store.ts:259-274`) copies any file an agent names into the library, where `/file` then serves it. It does not check that the file is a picture or video.

On their own these need the header. They are what make SEC-1, SEC-2 and SEC-5 serious. Fix: keep API outputs inside the library, and check file types in `adoptImage`.

### SEC-9. Smaller items from the Swift review (reported)

- API keys are passed to the engine and every child process through the environment (`Engine.swift:67-69`). Medium.
- `SCREENSHOTTER_ENGINE_DIR`, a custom Node path and the login shell's environment (including `NODE_OPTIONS`) are honoured in release builds, so local code can run inside the app and borrow its Screen Recording permission (`Engine.swift:28-31`). The bundled Node is signed with `disable-library-validation` and `allow-unsigned-executable-memory` (`scripts/signing.mjs:43`). Medium.
- Web Inspector is enabled in release builds. Low.
- The bundled Node is whatever version the build machine has; the app itself is not stapled, only the DMG. Low.
- `hooks/design-check.mjs` injects house-style notes into agents as instructions, which makes `/api/house-style` a way to plant instructions (see SEC-2). Low on its own.

### SEC-10. Upload size is only checked against the declared length (Low, verified)

`server.ts:1075-1083`. A chunked upload with no `Content-Length` is written to disk without limit. Count bytes in the stream.

## 2. Bugs

### Recording and the Swift app (reported, not re-checked)

- **BUG-1. A recording that dies is never noticed (High).** `SCStream` is created with `delegate: nil` (`Capture/Recorders.swift:340, 384-386`). If the display is unplugged or the window closes, recording appears to continue.
- **BUG-2. Quitting or crashing mid-recording loses the file (High).** No `movieFragmentInterval`, so an unfinished MP4 is unplayable (`Recorders.swift:91`, `AppDelegate.swift:123-131`). Set a fragment interval and finish the writer on quit.
- **BUG-3. A full disk or writer failure is silent, and the recording is discarded at Stop (High).** `Recorders.swift:144-151, 266-271`. Recordings run up to about 80 Mbps, so this is reachable.
- **BUG-4. Stopping during the countdown leaves a stream, the cursor timer and a parts folder behind (Medium).** `CaptureCoordinator.swift:322-352, 394-423`.
- **BUG-5. The export renderer can wait forever (Medium).** `RecordingRenderer.swift:242-247`.
- **BUG-6 (Medium to Low, reported):** imports read whole files on the main thread and swallow errors (`AppDelegate.swift:387-424`); a possible crash calling `startWriting()` again after a failure (`Recorders.swift:135-138`, plausible); no single-instance guard; the hotkey's registration result is ignored; the page is not marked not-ready when its web process dies (`AppDelegate.swift:242-244`); clipboard captures and parts folders are never cleaned up.

### Boards

- **BUG-7. A failed save loses the change but keeps it in undo (Medium, verified).** `board-state.js:228-246`. On a failed `/api/board/ops` the editor reloads from disk and drops the change. The undo stack still holds it, so the next ⌘Z applies the reverse of something that never happened, or fails with "Couldn't undo that". There is no retry, so every edit made while the engine restarts is lost. Fix: retry with backoff, and remove the entry from `B.past` if it is finally dropped.
- **BUG-8. Two imported SVGs can recolour each other (Medium, verified by code).** SVG `<style>` blocks are kept and are global to the page (`core.ts:371`). Illustrator and Figma exports both use class names like `.cls-1`, so the second SVG's rules restyle the first. Same root cause as SEC-1 point 3. Fix: inline the rules onto elements at import, or prefix class names per layer.
- **BUG-9. A damaged scratchpad file is replaced by an empty one (Medium, verified).** `store.ts:19-25, 111-123`: `read` returns nothing for a file that fails to parse, and `scratchpad()` then writes a fresh board over it. Fix: only create it when the file does not exist; otherwise move the damaged file aside and tell the user.
- **BUG-10. A damaged board silently disappears from the list (Low, verified).** `store.ts:140-153`.
- **BUG-11. Deleting a board while an agent writes to it can bring it back (Low, verified).** `deleteBoard` (`store.ts:232-238`) does not take the lock that `changeBoard` holds.
- **BUG-12. Two processes can hold a board's lock at once (Low, plausible).** `store.ts:40-66`: two waiters that both judge a lock stale can each remove it, the second removing the first's new lock. Also, any change that takes over 5 seconds has its lock taken from it.
- **BUG-13. Unsaved board edits can vanish (Low, verified).** `board-state.js:259-266`: if the waiting changes no longer apply after a reload, the queue is emptied silently. And only the view is saved on `pagehide` (`board-state.js:360`), so a change still queued at quit is lost. Show a notice, and flush on `pagehide`.

### Studio server

- **BUG-14. A file removed mid-request can crash the engine (Medium, plausible).** About ten routes do `createReadStream(file).pipe(res)` with no error handler (`server.ts:516, 533, 545, 660-675` and others), and the process has no `uncaughtException` handler. If the file goes between the existence check and the read, the stream's error is unhandled. Use `pipeline()` and answer 404.
- **BUG-15. Byte ranges are parsed loosely (Low, verified).** `server.ts:663-670`: `bytes=-500` (the last 500 bytes) is read as bytes 0 to 500, and a range past the end is answered with a wrong length. This can stall video seeking.
- **BUG-16. Saving on window close can silently fail for large designs (Medium, plausible).** `src/studio/ui/store.js:546-562` uses `fetch(..., { keepalive: true })`, which browsers cap at 64 KB per page. A set with many screens or a long chat is larger, and the error is swallowed. Fix: have the app ask the page to save and wait for the answer before closing, as `flushPersist` already returns a promise.
- **BUG-17. Designs are last-writer-wins (Medium, plausible).** `src/studio/scenes.ts` `saveScene` has no revision check, unlike boards. An agent's `save_scene` and the Studio's autosave of the same open design overwrite each other; the Studio only looks for agent changes every 5 seconds (`app.js:2008`).

### Studio canvas and controls (from the finished reviewer; first three re-checked)

- **BUG-18. Typing in a slider's number box uses raw units (High, verified).** `controls.js:76-80`. The box shows "100%" but reads the typed number as the raw value, so typing 120 for brightness gives 160%, and typing 5 for a 3% blur jumps to the maximum. Typing anything that is not a number resets the setting. About 55 sliders are affected.
- **BUG-19. Escape in a number field saves the typed value (Medium, verified).** `controls.js:119-131`. The blur fires before the draft is cleared. Enter commits twice, which adds two undo steps on boards.
- **BUG-20. Delete after undoing "add shape" throws (Medium, verified).** `store.js:284-293` only clears stale device, text and caption selections; a stale `shape-1` or `image-1` makes Delete throw in the global key handler (`actions.js:383, 388`).
- **BUG-21. A lost mouse-up leaves a drag stuck to the pointer (Medium, reported).** `canvas.js:791, 908, 1086`, `controls.js:111, 528`: no `pointercancel`, blur or Escape handling. Deleting during a drag writes the dragged position onto the next device.
- **BUG-22. The set row can show another screen's layout (Medium, reported).** `canvas.js:531-561`: a cache keyed by screen index that is never cleared, and stays wrong if the fetch fails.
- **BUG-23. Space and Tab are taken from the whole window (Medium, reported).** `canvas.js:848-854`, `app.js:1752-1770`. Space pans and never reaches a focused button; pan mode sticks after switching apps. Tab always cycles canvas items, so the interface cannot be used by keyboard.
- **BUG-24. Enter while composing Japanese, Chinese or Korean text ends the edit (Medium, reported).** `canvas.js:499` has no composition check.
- **BUG-25 (Low, reported):** emptying a text leaves the selection on the wrong text (`canvas.js:1111`); the colour picker drops transparency (`controls.js:308`); ⌘B across a line break joins the lines (`controls.js:781`); popovers do not follow scrolling and one Escape closes all of them (`controls.js:205-228`); dropdown arrow keys only work when there is a search box (`controls.js:259-281`); a dropped item can snap back for a moment (`canvas.js:719`, `store.js:297`).

## 3. UI and UX

### Native app (reported)

- **UX-1. Menu commands do nothing when the Studio window is closed** (`AppDelegate.swift:428-431`), and **clicking the Dock icon never brings the window back** (`:114-117`). Reopen the window in both cases.
- **UX-2. Settings kept in the page are forgotten on every launch.** The web view uses a non-persistent store and a new port each time, so `localStorage` (last board, each board's zoom and page) never survives. Use a fixed origin or keep these in the engine's state file.
- **UX-3. Screen Recording permission is asked twice and the grant is not noticed until relaunch** (`CaptureModel.swift:265-274`).
- **UX-4. An engine failure at launch shows nothing useful.**
- **UX-5. The region picker can only be cancelled with Esc; the ⌘⇧2 hotkey cannot be changed; the capture bar lacks accessibility labels.**

### Studio (from the finished reviewer)

- **UX-6. Shared controls are mouse-only and unlabelled.** Sliders have no keyboard support or slider role, section headers are clickable `div`s, dropdowns and segmented controls have no state for assistive tech (`controls.js:37, 69, 164, 273`). Fixing them in `controls.js` improves the Studio and Boards together.
- **UX-7. Text fields have no focus ring** (`styles.css:72`).
- **UX-8. Missing files look like nothing.** A moved screenshot shows an empty device frame with no message (`canvas.js:319, 326, 407`). Show "Screenshot missing · Replace…".
- **UX-9. Screens still loading in a set are blank gaps** (`canvas.js:868-873`). Show a placeholder, and a retry on failure.
- **UX-10. Double-click to reset a slider is undiscoverable, and number fields have no reset at all** (`controls.js:70`).
- **UX-11. A slow slider drag becomes several undo steps** (`controls.js:63-66`); send one final change on release.
- **UX-12. Headline and subheadline cannot be edited in one go** (`canvas.js:505-516`): moving between them closes the edit.
- **UX-13. A size can only be removed by right-click** (`canvas.js:1297`).
- **UX-14. Resize handles drift from the pointer on text** (`canvas.js:1052`).

### Boards (my read)

- **UX-15. Save failures are easy to miss.** One toast, then the canvas quietly returns to the saved state (BUG-7). A persistent "Not saved · Retry" state would be clearer.
- **UX-16. Undoing "An agent's change" replaces the whole board with a snapshot** (`board-state.js:268-277`). It works, but it also reverts anything else the agent did in the same poll, with no preview of what will go. A label such as "Undo agent's change to <artboard>" would help.
- **UX-17. A deleted board that was open last time shows an error at launch** (`board-state.js:309-327`, `app.js:2017`). Drop `board:last` quietly instead.

## 4. Performance

- **PERF-1. Caches are never cleaned (verified, measured).** `src/util/files.ts:97` puts them in `~/.cache/screenshotter`, and nothing removes old entries. On this Mac it holds **1.4 GB**: 419 MB of bezel downloads, 338 MB of finishes, 241 MB of wallpapers, 177 MB of Unsplash photos. `board-artboards` gains a file for every board revision put in a device (`server.ts:918`). Fix: delete installers after import, cap each folder by size and age at startup, and consider `~/Library/Caches`.
- **PERF-2. An open board re-reads and re-parses its whole file every 0.7 s (verified).** `board-state.js:287` polls `/api/board/rev`, and `server.ts:627-633` answers by parsing the full board JSON and the comments file. Each Preview tab adds another poll every second. Fix: remember `rev` by the file's modification time, or keep it in a small file beside the board.
- **PERF-3. The Boards shelf parses every board every 3 s (verified).** `board-library.js:23` → `listBoards` (`store.ts:140-153`), which reads every board in full to build a short summary. Cache summaries by modification time.
- **PERF-4. The library list reads a JSON file per export before trimming to 80 (verified).** `server.ts:330-343`: `exportScene` runs for every file in `mockups` and `videos`, then the list is cut. Sort and cut first.
- **PERF-5. Board assets are never removed (verified).** Pictures and videos copied into `.studio/boards/assets` (`store.ts:259-274`) stay after their layer or board is deleted. Videos make this grow fast.
- **PERF-6. Hovering re-renders more than the canvas (verified for boards, reported for the Studio).** `board-canvas.js:573, 587` and `canvas.js:1197-1201` write the hovered item to the shared store, so the layer list and inspector re-render on every hover change. The layer list draws every open row with no windowing (`board.js:209-230`). Keep hover local to the canvas.
- **PERF-7. Every agent change stores two full copies of the board in undo (verified).** `board-state.js:268-277`, up to 100 entries. Undoing one posts the whole board back. Store a diff, or cap agent entries.
- **PERF-8. Waiting for a board's lock blocks the whole engine (verified).** `store.ts:34, 40-66` waits with `Atomics.wait` for up to 8 seconds; nothing else is served meanwhile.
- **PERF-9. Small pictures travel as base64 inside JSON (verified).** `server.ts:192-207` (`shotThumb`) and the strip builder at `:266-282` read files synchronously and inline them. Serve them as files so the browser can cache them.
- **PERF-10. Swift (reported).** A login shell and `node --version` run before every engine start; recording is fixed at 60 fps H.264 at about 60 Mbps for 4K with no HEVC or 30 fps option; saving with the camera re-encodes the whole video; the export renderer is single-threaded and busy-waits (`RecordingRenderer.swift`).

## Suggested order

1. **SEC-1, SEC-2, SEC-3, SEC-4** together: they form one chain from hostile content to the Mac. SEC-3 and SEC-4 are a few lines each in Swift; SEC-2 is a second browser instance; SEC-1 is the larger change.
2. **BUG-1, BUG-2, BUG-3**: lost recordings.
3. **SEC-5, SEC-6**: a per-launch token and safe file serving close most of what is left.
4. **BUG-18, BUG-19, BUG-20, BUG-7, BUG-9**: wrong values and lost work in everyday use.
5. **PERF-1, PERF-2**: disk use and constant re-parsing.
6. A second audit pass over the areas listed as not reviewed.
